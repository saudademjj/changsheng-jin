# 《长生烬》文案质检宪章与封板协议（Copy Audit Protocol）

> **目的**：终结“复查 → 通过 → 再复查又一堆问题”的无限循环。将客观可判定问题彻底交由自动化代码防线拦截，将人工 / AI 语义审校严格约束在**单轮分块 + 客观硬伤 + 明确封板门禁**之内。

---

## 一、三层防线总览

| 层级 | 实现位置 | 职责 | 阻断策略 |
| --- | --- | --- | --- |
| **Layer 1 · 全源静态双区词法扫描** | `src/engine/__tests__/copyAudit.test.ts` | 使用 TypeScript AST 扫描 `src/content/`、`src/engine/`、`src/ui/` 全部玩家可见字符串，按「沉浸正文区 / 机巧提示区」分别校验出戏词、错别字、病句、占位符、数字/百分号规范与定稿名句锁 | **硬阻断**（接入 `npm test`、`npm run audit:copy` 与 CI） |
| **Layer 2 · 双引擎动态状态穿帮测试** | `src/engine/__tests__/copyAudit.test.ts` | ① **高危正交状态矩阵**：批量注入亡者/永封/未重塑/未遇/敌对/夏雪/三性称谓/低线索迷雾，遍历全场景、雅阁、世局、传记、前尘余波与十二结局校验不变量；② **固定种子多路径六幕通关跑图**：模拟真实玩家多出身多性别跑完六幕，校验历法恒等式、跨步连携、空段与占位符 | **硬阻断**（接入 `npm test`、`npm run audit:copy` 与 CI） |
| **Layer 3 · 受控分块 AI 终审与封板签收** | 本文档第六、七节 + `AGENTS.md` | 按固定十切片逐块执行**唯一一轮**客观审校；修完仅做 **Git Diff 复核**，严禁对已签收且未改动区块重复发起全库开放式挑刺 | **封板门禁**（P0/P1 清零即封板，P2 全冻结） |

### 日常校验命令
```bash
npm run audit:copy   # 单独运行全源双区词法 + 双引擎状态模糊测试（秒级）
npm run typecheck    # TypeScript 严格类型校验
npm test             # 全量回归（engine.test.ts + copyAudit.test.ts）
npm run build        # 生产构建校验
```

## 二、双区语境规范（Zone Policy）

为避免“盲玩信息清晰度”与“古风沉浸去第四面墙”反复左右互搏，仓库内所有玩家可见文案严格划分为两个区域，执行不同红线：

### Zone A · 沉浸正文区（严格古风沉浸）
**覆盖范围**：
- 场景正文与演绎：`paragraphs`、`outcome`、`bridgeNote`、`venueDesc`
- 终局与设定叙事：`epilogue`、`poem`、`bio`、`chronicle`、`letters.body`、`excerpt`、`opening/world` 叙事描述
- 仙缘雅阁与世局叙事：`sanctuary.ts` 互动剧情与尺素、`worldview.ts` 势力/疆域/前尘余波叙事正文、`economy.ts` 坊市风声 `rumorText`

**硬性红线**：
1. **零现代网词 / 现代金融与工程黑话**：严禁出现如「不讲武德、怂货、搬砖、辩经、算盘精、平仓、止损、杠杆、折现、零耗时、低吸高抛、八五折、倒计时、证伪、证据链、微操、KPI、CPU、暴雷、画大饼、工具人、剧情杀、发便当」等出戏词汇。
2. **零第四面墙系统词**：正文中严禁出现「真结局、隐藏结局、普通结局、好感度、触发、解锁、进度条、存档、读档、周目、攻略、机制、数值、系统提示、路线分支、伏笔回收、宿缘回收」等元游戏词。
3. **零错别字与高频病句**：拦截「双剑合壁（应为璧）、出手果绝（应为决）、重倒覆辙、再接再励、迫不急待、一愁莫展、墨守成规、走头无路、阴谋诡计、与……与……（双与病句）」等。
4. **零模板残余与非法值**：渲染结果不得出现未替换 `{{...}}`、`undefined`、`NaN`、`[object Object]` 或首尾异常空段。
5. **数词与比例规范**：古风叙事正文中禁止 `%` 与加减号数值（如 `+10`、`-8 载`、`45%`）；岁数、成数、年限统一用中文数词（如「约余四成半」「五百二十载」）。

### Zone B · 机巧提示与 UI 区（清晰与雅致并重）
**覆盖范围**：
- 抉择辅助说明与反馈：`subtext`、`insightTags`、`notice`、`lockReason`、`summary`、`checkpointLabel`、`logSummary`
- 前端界面组件：`src/ui/*.tsx`（顶部栏、命盘/行囊/坊市/世局/雅阁抽屉、开局引导、封皮与终局按钮）
- 天机洞见开启时的精准数据说明

**硬性红线**：
1. **允许清晰的功能与数值门槛提示**（例如破境战力/心境/灵石门槛、坊市价格、终局预警），保障盲玩公平性；**但闭关模式（`tianjiInsight = false`）严禁泄露原始数字进度**。
2. **仍严格禁止现代网梗、粗俗口语与错别字**（如「买个教训、不讲武德、搬砖、双剑合壁」等一律拦截）。
3. **统一修仙雅称**：
   - 流程中的结局提示统一用「**终局 / 收束此世**」，严禁在场景与选项中泄露「真结局 / 隐藏结局」（通关后的终局展卷与万象志徽章 `endings.ts` 保留 `真结局` 档位标识）；
   - 灵脉残存等世界观指标用中文成数（如「约余四成半」），不用 `%`；
   - 扣减寿元用「**寿元折损 N 载**」，严禁拼接出「寿元增延 -N 载」。

## 三、客观因果与状态不变量红线（Layer 2 守卫）

以下规则由 `copyAudit.test.ts` 通过**正交极限状态矩阵 + 固定种子多路径跑图**自动检验，新增或修改剧本后发现的新穿帮，**必须同步沉淀为一条新的不变量或用例**，杜绝同类复发：

1. **生死守卫（苏知微）**：`deceased === true` 或 `flags.su_zhiwei_passed === true` 时，全场景、雅阁、世局、前尘余波、结局中绝不可复活、并肩现身、寄出新信或弹出「心生亲近 / 默契渐深」通知；仅允许阿芸续灯或焚香追思（好感零变动）。
2. **封印与塑身守卫（苍溟）**：
   - `cangming_sealed` / `act4_cangming_sealed` 为真时，绝不可发声、参战、围炉或保留 `daoPartnerId === 'cang_ming'`；
   - 未获 `cangming_reborn` 时，仍为焦黑断玉残魂，雅阁与正文绝不可出现「抱臂、举杯共饮、两坛烈酒、并肩踏雪」等实体肉身动作。
3. **幽灵故人守卫（未遇 / 敌对）**：
   - `met === false` 时，除明确引介/传闻场景外，群雄会、终战前夜、前尘余波、结局绝不可出现该故人亲近相助或称呼旧交；
   - `stance === 'rival' | 'estranged'` 时，不得保留道侣身份，亦不得以温情知交口吻同框。
4. **剧透迷雾守卫**：卷一（0 线索）及低勘验阶段，全部可见文本（含传记、六方势力、九州疆域志、六境阶梯、天机勘验）严禁提前泄露「牧灵骗局、收割大期、伪天门、天门九枢、灵根牧种、九剑尊血战、斩天四代、兄长失踪、转运井」等中后期核心谜底。
5. **季节守卫**：春夏秋（`seasonIndex ∈ {0, 1, 2}`）渲染通用场景与结局时，非恒雪地理白名单外，不得凭空出现「残雪、大雪纷飞、积雪」等季节错乱描写。
6. **三性称谓守卫**：以 `male` / `female` / `other` 分别渲染全库，不得残留未插值 `{{robe}}` / `{{dormMate}}` / `{{honorific}}`，女性/中性主角路径下不得误现「平辈兄弟、小子、男儿」等单性别硬编码称呼。
7. **历法恒等式守卫**：任意多步游玩路径中，始终满足 `year - Math.floor(ageMonths / 12) === 2996`，且瞬死抉择不额外推进时间；卷二/三/四闭死关水磨（`slow_grind`）均受 `maxUsesInAct: 1` 限制，防无限刷年击穿长明历。
8. **世界观与路由知识守卫（Phase 1+2 终审沉淀）**：
   - 全站静态拦截已清零地理/物价/法则/断代穿帮词（「江南茶楼、山下青州城、半张破障符、一文钱能买三捆、中州七十二城、斩天会四代遗录、一网收尽」），Zone A 同步拦截「坏账、挤兑、沉没成本、船票、豁免券、积分、成色分级」；
   - 未获 `clue_gate_weakness` 时，卷五风雪夜、枢纽与卷六不得提前预知「九枢 / 东侧三座阵眼」且锁定双剑/孤剑破枢；未获无灵线索及归尘印时，半步自封改用「枯石龟息秘术」；
   - 苏知微按纯年龄+病况结算生死（卷四高龄跳过槐阴入卷五时即时结算辞世，绝不同屏生死互殴或瞬移回杏林），【九转延寿露】单周目服后不复刷；沈清霜 `shen_saved_from_sect` 跨卷离宗状态同步，背叛缺席卷三线破囚孤身截击；`baibao_token` 不静态绕过死手；单周目可合法集齐 `12/12` 天机残卷。

## 五、缺陷分级与封板门禁（Freeze Gate）

每次人工或 AI 审校，**必须严格按以下三级分类报告问题**；凡不满足证据要求的条目一律视为无效噪音，不得动笔修改：

- **P0 · 客观硬伤（阻断封板，必改 + 必补防线）**
  - **准入门槛**：必须同时给出 `文件:行号`、`触发条件/状态` 与 `客观矛盾事实`。
  - **范围**：状态/因果穿帮、提前剧透、错别字与明显语病、违反双区词法红线的出戏词、未替换占位符/数值错乱、类型或测试失败。
  - **闭环要求**：修复后，若属于可泛化的规则/状态漏网，须同步在 `copyAudit.test.ts` 中追加对应规则或断言。
- **P1 · 客观结构瑕疵（限当前切片内一次性处理）**
  - **准入门槛**：必须贴出前后原文对比，证明存在客观的**上下文衔接断层、同场景大段自重复、或同一人物同一场景语气剧烈割裂**。
- **P2 · 主观文风偏好（复查阶段全面冻结）**
  - **范围**：诸如“此句略显平淡”“可润色得更有古意”“节奏可更紧凑”“建议换个更华丽的比喻”等主观审美建议。
  - **禁令**：**一律禁止在复查阶段提出、禁止擅自改写**。除非用户亲自阅读后点名要求改写某一句。

### 正式封板退出条件（满足即停手）
1. `npm run typecheck && npm run audit:copy && npm test && npm run build` 全部通过；
2. 下表 10 个固定切片均完成**唯一一轮**客观审校且 P0 / P1 清零；
3. 若本轮有修改，仅对本次 `git diff` 涉及的改动行与关联分支做**一次 Diff 复核**，通过即在签收表标为 `已封板`；
4. **已封板切片禁止再次发起开放式全量重审**。日后仅当该切片有新增功能或用户明确点名修改时，才针对改动增量重检。

## 七、受控分块终审标准指令模板（供后续单轮终审使用）

当需要对某个切片执行唯一一轮终审时，直接向审校 Agent 下发以下约束（严禁使用“再帮我看看还有什么问题”之类的开放式指令）：

> 你正在执行《长生烬》**Slice XX** 的受控终审，必须严格遵守 `docs/COPY_AUDIT_PROTOCOL.md`：
> 1. **只报告 P0（客观穿帮/剧透/错别字/双区词法违规/占位符错误）和 P1（明确上下文断层或同场景大段自重复）**；
> 2. **绝对禁止报告或修改任何 P2 主观文风润色建议**；如果你确认该切片没有 P0/P1，请直接回复 `PASS（0 P0 / 0 P1）`，不要硬凑问题；
> 3. 每条问题必须提供 `文件:行号 + 触发状态 + 原文摘录 + 客观矛盾说明 + 最小改动方案`；
> 4. 严禁修改「定稿名句保护锁」中的任何句子。
